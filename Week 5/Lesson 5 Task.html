Parallel Processing Mini-Project OR Audio Middleware Mini-Project

Estimated Time: 3–6 hours

Submission: GitHub

Task Brief

Design and implement a parallel computation system to process image data in your chosen game engine. This task focuses on using multithreading or job systems to achieve high-performance pixel analysis.

Your system should:

  • Load an image or texture from disk.

  • Calculate the sum of all red (R) channel values of an image using:

    • Unity: the Jobs System with Burst Compilation for maximum performance.
    • Unreal: the ParallelFor or TaskGraph system for multithreaded processing.

  • Log Execution Time

Deliverables

  • Implementation files (Unity project or Unreal C++/Blueprint project).

  • Media evidence:

    • .gif or short video showing the computation and log results.
    • Screenshot(s) of the survey and log output.

  • 500-word technical commentary (COMMENTARY.md) describing:

    • How multithreading or jobs were implemented.
    • What benchmarking or telemetry data was collected.
    • Tools, frameworks, or APIs used (e.g. Unity Burst, Unreal ParallelFor).
    • How performance results could inform optimisation.

Optional Ideas

  • Compare single-thread vs multithreaded performance.
  • Visualise execution time using a simple chart or external tool.
  • Export telemetry to CSV or JSON for further analysis.
  • Extend the system to process multiple images or colour channels concurrently.

Task Brief

Integrate a professional audio middleware system into your game engine of choice, and demonstrate it in a fully built project (e.g. Windows build).

Your system should:

  • Integrate either FMOD or Wwise into your project.
  • Create and trigger a sound event (e.g. background music, sound effect, or interaction cue).
  • Ensure the event plays correctly within the built version of the game.

Deliverables

  • Integrated project (FMOD/Wwise implemented and playable).

  • Media evidence:

    • .gif or short video demonstrating the audio event in a built project.

  • 500-word technical commentary (COMMENTARY.md) describing:

    • How FMOD or Wwise was integrated.
    • What event(s) were triggered and logged.
    • How you validated the middleware in a packaged build.

Optional Ideas

  • Add multiple events or adaptive audio based on gameplay state.
  • Use middleware profiling tools to monitor real-time performance.
  • Log additional data such as listener position, sound radius, or trigger count.
  • Compare the middleware’s CPU or memory usage to the engine’s native audio system.
