# Artificial Intelligence Commentary

## How the AI model or system was implemented or connected
To get a local large language model running inside Unity without paying for a cloud API or dealing with external network lag, I set up a local Ollama server running llama3.23b on my PC and connected it to a custom C# controller. Whenever I type a message in Unity and press send, the script uses a coroutine and UnityWebRequest to POST the JSON chat data to http://localhost:11434/api/chat. Running the request asynchronously stops the game from freezing whilst waiting for inference to finish. Inside the script, I maintain a conversation history list alongside a character system prompt, serialise the data with JsonUtility, parse the returned reply and append it to the chat UI. I also added personality switching so I can change who I am talking to on the fly by clearing the old chat history, loading a new system prompt and refreshing the scroll view.

## What data was processed or generated
The system processes plain text entered by the player alongside character system prompt and previous system, user and assistant messages structured as JSON chat objects. Ollama processes the context and generates natural dialogue replies for the active character personality, plus execution statistics in the response payload. Alongside the visible chat messages, the script processes and writes performance telemetry to a local CSV file after each response. Each row records the timestamp, model name, Ollama version, active personality name, prompt and generated token counts, total duration, model load duration, prompt evaluation duration, token generation duration, calculated tokens per second, Unity round trip response time and my platform and hardware details including OS, CPU, core count, system RAM, GPU and VRAM.

## Tools, frameworks, or APIs used (e.g. Ollama, TensorFlow, Hugging Face, Unity ML-Agents, Unreal ML Deformer)
I built the project in Unity 6 using C# and connected it to Ollama hosting the Llama 3.2 model locally on localhost:11434. Network requests and JSON handling use UnityEngine.Networking.UnityWebRequest and UnityEngine.JsonUtility querying Ollama's /api/chat and /api/version endpoints. For the user interface, I used TextMeshPro (TMP_InputField, TMP_Text, and TMP_Dropdown), standard UI buttons and a ScrollRect paired with a VerticalLayoutGroup and ContentSizeFitter so longer replies resize properly and scroll without breaking or snapping back. For telemetry and hardware logging, I used System.Diagnostics.Stopwatch, UnityEngine.SystemInfo, and System.IO.

## How AI enhanced gameplay, creativity, or production workflow
Using a local LLM makes NPC interactions feel much more reactive towards the player and open ended than hard coded dialogue trees because characters can respond naturally to whatever I type while staying in character. Defining personalities through system prompts, such as a nervous tavern keeper or an angry gamer, makes it quick and easy to experiment with character voices and constraints without writing separate dialogue branches for every possible line. Creating and using a drop down menu also allows new characters to be created as all I need to do is press the plus symbol, give it a name and then create a prompt with as much or as little detail as I see fit. Running everything locally and logging telemetry data to CSV also improves testing and evaluation as I can measure real response times, spot model load overhead, see how token counts affect speed and compare performance directly on my own hardware inside Unity.
